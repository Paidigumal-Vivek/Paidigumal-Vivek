# Project Artifacts & Data Governance

## Source files used during the assessment

The completed working set included:

- `RAW CAD DATA.xlsx` — one-year CAD source data
- `VIVEK_Kent_Assesment.pbix` — completed Power BI dashboard
- `Vivek Presentation.pptx` — presentation deck
- `Practical Exercise.pdf` — assessment brief

## Public portfolio policy

The analytical documentation is published here, but operational/source artifacts should **not** be committed to a public repository unless their release has been explicitly authorized.

This is especially important for:

- Raw CAD data
- Power BI files that embed source data
- Files containing agency-specific operational information

The project documentation is therefore designed to demonstrate the analytical work without unnecessarily publishing source records.

## Recommended portfolio evidence

For a public portfolio, prioritize:

1. README and project overview
2. Methodology and data dictionary
3. Findings and operational considerations
4. Sanitized dashboard screenshots
5. Sanitized presentation slides
6. DAX / analytical logic documentation

If the underlying assessment files are later approved for publication, they can be added under `data/`, `dashboard/`, and `presentation/` with clear provenance and access notes.

## Responsible-use statement

This repository documents an analytical assessment and is not an operational law-enforcement product. Findings should not be interpreted as real-time intelligence or used for operational decisions without appropriate agency validation and context.
